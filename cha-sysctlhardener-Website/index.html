A day book kept in ruled columns. The work is over, the objects remain, and each one is accounted for on the page.

Validate the Configuration Check Against the Policy Run the Dry Run Flag Show Help

Report Only, Never Rewritten

cha-sysctlhardener validates a YAML or JSON configuration file against a hardening policy written as a JSON schema, and reports every setting that does not comply, with the schema failure for each one.

It does not rewrite the configuration file. The report is the output, and a non compliant configuration exits with status 1 so scripts can gate on it.

The repository on GitHub

Install

git clone https://github.com/ShadowGuard-AI/cha-sysctlhardener

Install Stops at the Clone

Gap, not instruction: the source install stops at the clone. It gives no change of directory step and no requirements install, even though a requirements.txt sits in the repository naming jsonschema and PyYAML.

Two Required Files

python3 main.py -c CONFIG_FILE -p POLICY_FILE [-n]

Both file arguments are required, and the bracketed flag is the only optional part.

The Dry Run Changes Nothing

-hShows the help message and exits.
-c, --configPath to the configuration file, YAML or JSON, required.
-p, --policyPath to the JSON schema policy file, required.
-n, --dry-runAsks for a dry run, showing changes without applying them. Every run of this tool is report only, so this flag does not change the output or the exit code, and a non compliant configuration still exits 1 with this flag.

Exits That Were Verified

A compliant configuration exits 0.

A non compliant configuration exits 1 and reports the schema failure for each setting.

A missing configuration file exits 1.

Non Compliant Means Exit 1

Read from main.py, not from the source document: the validator gathers every failure instead of stopping at the first, nothing in the code is specific to sysctl despite the name, and a malformed policy can surface in the same error list as a fault in the configuration.
